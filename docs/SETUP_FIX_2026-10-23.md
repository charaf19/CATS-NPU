# Windows bitonic construction repair — 2026-10-23

## Completed

Dependency installation in the pasted setup log succeeded. The setup script
then stopped because its pytest command failed. The failure was reproduced
without changing installed packages.

In `src/cats_npu/backends.py`, explicitly normalize the XOR permutation array
using `.astype(np.int32)` before constructing OpenVINO constants. On the current
Windows/NumPy/OpenVINO installation, XOR produced dtype character `i` / number 5
(`np.intc`), which OpenVINO rejected even though it printed `int32`. The explicit
cast yields dtype character `l` / number 7 and is accepted. No score conversion
or selection-policy change was introduced.

Add four parametrized regression cases in `tests/test_openvino_optional.py`:
FP16/FP32 at widths 2 and 16, each checking K=1, half width, and full width where
distinct, over mixed scores, equal scores, and internal `-inf` padding. These
tests inspect raw CPU bitonic outputs, without host merge or tie repair.
